# Website Tester — учебный инструмент автоматизации QA

Универсальный скрипт для автоматизированного тестирования веб-сайтов на
Playwright. Написан специально для практики: код разбит на понятные блоки
с подробными комментариями — что делает каждая функция и почему именно так.

## Что проверяет

1. **Smoke-тест** — код ответа сервера (200) и скорость загрузки (< 3с)
2. **UI/UX**:
   - скриншоты в трёх разрешениях (мобильный/планшет/десктоп)
   - горизонтальный overflow (когда контент шире экрана — частая проблема адаптивной вёрстки)
   - битые ссылки (все `<a href>` проверяются на реальный код ответа)
   - битые картинки (все `<img>`, которые не загрузились)
3. **Тестирование форм** — находит все формы, заполняет позитивными и
   негативными тестовыми данными (пустые поля, невалидный email, спецсимволы),
   проверяет встроенную браузерную валидацию
4. **Отчётность** — текстовый лог + наглядный HTML-отчёт со сводкой

## Важно про тестирование форм — прочитай перед использованием

По умолчанию скрипт **не отправляет формы по-настоящему** — только
заполняет их и проверяет `checkValidity()` (встроенную браузерную
валидацию). Это осознанное решение: реальная отправка на чужой сайт без
разрешения означала бы, например, отправку тестовых писем на реальную
почту компании.

Если хочешь проверить и серверную обработку (реальный клик по кнопке
"Отправить") — в `config.py` есть флаг `ACTUALLY_SUBMIT_FORMS`. Включай его
**только** на своих сайтах или в тестовой среде.

Аналогично: направляй скрипт только на сайты, которыми владеешь сам, или на
которые есть явное разрешение тестировать. Список по умолчанию указывает на
специальные учебные сайты, созданные именно для практики QA-автоматизации.

## Установка

```bash
pip install -r requirements.txt
playwright install chromium
```

## Запуск

```bash
python website_tester.py
```

Список сайтов и все настройки — в `config.py`, менять основной код для
этого не нужно.

## Результаты

После запуска в папке `reports/` появятся:
- `report.html` — открой в браузере, наглядная сводка с цветовой индикацией
- `report.txt` — простой текстовый лог, удобно для быстрого просмотра в консоли
- `screenshots/` — скриншоты каждого сайта в каждом разрешении

## Структура проекта

```
website_tester.py   — основной скрипт (все функции проверок + отчётность)
config.py            — список сайтов, разрешения экрана, тестовые данные форм
requirements.txt
```

## Что реально нашёл этот скрипт при тестировании (для примера)

При обкатке скрипта на реальном сайте он поймал настоящую проблему —
горизонтальный overflow: контент страницы оказался шире экрана даже на
мобильном разрешении (375px виден контент шириной 2288px). Это пример
того, зачем вообще нужна такая автоматизация — руками пролистать все
разрешения на каждом сайте долго, а скрипт находит такое за секунды.
